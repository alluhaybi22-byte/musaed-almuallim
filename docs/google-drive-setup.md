# Google Drive: إعداد معلّق، تكامل قابل للاختبار

حالة هذه المسودة: كود الحفظ والاستعادة موجود، و`GOOGLE_DRIVE_CLIENT_ID` فارغ عمدًا. لم يُنشأ OAuth client ولم تُختبر موافقة Google أو عملية رفع حقيقية. في 20 أكتوبر 2026 تعذّر فتح صفحة Google Cloud من المتصفح المتاح (`Site Unavailable`) حتى بعد إعادة تحميل واحدة. اتصال Google Drive داخل المحادثة مستقل عن تفويض التطبيق ولا يُنقل إليه.

## خطوة التفعيل

1. افتح Google Cloud بحساب مالك التطبيق. استخدم عميل OAuth مستقلًا لمساعد المعلم؛ لا تغيّر عميل تبيان أو تستخدم أسراره. إذا استُخدم مشروع تبيان السابق، تبقى شاشة التفويض وإعدادات النشر مشتركة بين عملاء المشروع؛ لا تغيّرها دون مراجعة أثرها على تبيان.
2. فعّل Google Drive API، وراجع شاشة التفويض والجمهور. للاختبار الشخصي أضف حساب المالك إلى مستخدمي الاختبار؛ لا تنشر شاشة التفويض للجميع تلقائيًا.
3. أنشئ OAuth client من نوع Web application باسم مساعد المعلم، مع Authorized JavaScript origins المطابقة حرفيًا لرابط التشغيل. الرابط الحي المعروف في هذه المحادثة: `https://app-0gwwi6.v2.appdeploy.ai`. لا تضف عنوان Cloudflare مفترضًا؛ النشر عليه لم ينجح بعد. يضاف الأصل الفعلي عند وجوده والتحقق منه.
4. اطلب النطاق الوحيد `https://www.googleapis.com/auth/drive.appdata`. لا يحتاج التطبيق صلاحية قراءة جميع ملفات Drive أو كلمة مرور أو Client Secret أو API key.
5. ضع Client ID العام فقط في `src/drive-config.js`. تحقق من أن العميل مستقل ومطابق للمشروع والأصول قبل تعديل القيمة. لا تضع أسرارًا في المستودع أو تطلبها عبر المحادثة.
6. ابنِ وانشر النسخة على الأصل المصرّح به، ثم اختبر الحساب الحقيقي: ربط، حفظ نسخة تجريبية، إعادة ربط في نافذة مستقلة، معاينة واستعادة، وإنهاء الجلسة. لا تعتبر اختبارات المحاكاة إثباتًا لعمل OAuth أو CORS الحقيقيين.

## سلوك الميزة

- البيانات المحلية هي أساس العمل؛ لا رفع عند تحميل التطبيق أو الدخول إلى الإعدادات أو ربط Google.
- تُحمّل مكتبة Google الرسمية فقط بعد طلب المستخدم تجهيز الدخول؛ الضغط التالي يفتح اختيار الحساب مباشرة للحفاظ على دعم النوافذ المنبثقة في الجوال.
- الحفظ يتم بزر مستقل ويُنشئ ملف JSON جديدًا في `appDataFolder` مع `appProperties.application = al-musaed`. لا يستبدل أو يحذف النسخ السابقة، ولا يقرأ ملفات Drive العادية.
- كل نسخة تتضمن الطلاب والنتائج والمسودات والإعدادات فقط. رموز الدخول تبقى في الذاكرة ولا تدخل IndexedDB أو النسخ أو السجلات.
- الاستعادة تبدأ بقراءة بيانات النسخة والتحقق منها ثم معاينة الأعداد. لا يكتب التطبيق البيانات المحلية قبل تأكيد الدمج. السجلات الموجودة بنفس المعرّف لا تُستبدل، وتُستعاد الإعدادات فقط عند اختيار المستخدم.
- هذه ميزة نسخ احتياطي واستعادة، وليست مزامنة تلقائية أو حل تعارضات بين جهازين. لا تعد المستخدم بتطابق البيانات لحظيًا.
- عرض 30 نسخة في الصفحة، مع زر للنسخ الأقدم؛ لا يتم قص القائمة دون إمكانية المتابعة.
- الحد 20 مليون بايت، مثل حد الاستعادة المحلية. يتوقف الرفع على شبكة بطيئة بعد 30 ثانية؛ لا تحدث إعادة رفع خفية، ويمكن للمستخدم المحاولة مجددًا. فشل الطلب بعد وصوله قد يترك نسخة منفصلة في Drive؛ لا توجد ضمانة exactly-once.
- إنهاء جلسة Google يزيل رمز الوصول من هذه الصفحة ولا يحذف الملفات أو يلغي منحة التطبيق من حساب Google. انتهاء الجلسة وإعادة تحميل الصفحة يستلزمان الربط مجددًا.
- النسخة المحلية `file:` تستمر دون شبكة؛ Google Drive متاح من أصل HTTPS مصرح به فقط. لا تُحمّل مكتبة Google أو تتصل بها النسخة غير المهيّأة.
- توسعة CSP محددة لمكتبة Google ونطاق API وإطار التفويض، مع إبقاء حماية كلمة المرور للـWorker الخاص دون تغيير.

## التحقق

`npm test`: 41 اختبارًا، منها 8 تغطي الرفض وانتهاء الجلسة وحصر الصلاحيات ورفع نسخة جديدة والتحقق من المضيف ومن النسخة وعدم تغيير الحالة المحلية.

`npm run test:drive`: محاكاة Google SDK وDrive داخل متصفح الاختبار. يفحص عدم الرفع دون طلب، نسختين منفصلتين، استعادة على جهاز ثانٍ ومعاينتها، خيار الإعدادات، منع التكرار، وفشل 401 وبقاء البيانات المحلية وعدم حفظ رموز الدخول.

نجحت كذلك اختبارات النسخة المستقلة دون شبكة. يجب تشغيل اختبارات التطبيق والاستماع عند كل تغيير في ملفات التكامل أو البناء.
